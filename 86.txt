# Smart Pointers in C++
Last Updated : 28 May, 2026
- 
- 
- 

A smart pointer is a class that wraps a raw pointer and automatically manages the lifetime of dynamically allocated memory.

- It ensures proper resource deallocation by automatically releasing the memory when the pointer goes out of scope, thus preventing memory leaks and dangling pointers. 
- Smart pointers are defined in the &lt;memory&gt; header and include types such as std::unique_ptr, std::shared_ptr, and std::weak_ptr.

****Example:**** Problem with Raw Pointers (Memory Leak Example)

            C++

    #include &lt;iostream&gt;
using namespace std;

int main() {
    while (1) {
        int* ptr = new int;
    }
    return 0;
}



****Explanation:****

- Memory is allocated repeatedly using new.
- The allocated memory is never released using delete.
- This results in a memory leak, eventually exhausting system memory.
## Types of Smart Pointers

### 1. auto_ptr (Deprecated)


auto_ptr was an early smart pointer that automatically deleted the managed object when it went out of scope.
![auto_pointer_in_c_](https://media.geeksforgeeks.org/wp-content/uploads/20260119112713642844/auto_pointer_in_c_.webp)Auto Pointers in C++
            C++

    #include &lt;iostream&gt;
#include &lt;memory&gt;
using namespace std;

int main() {
    auto_ptr&lt;int&gt; ptr1(new int(10));
    cout &lt;&lt; *ptr1 &lt;&lt; endl;

    auto_ptr&lt;int&gt; ptr2 = ptr1;  // ownership transfer
    cout &lt;&lt; *ptr2;
    return 0;
}

**Output**10
10

****Key Points:****

- Ownership is transferred, leaving the original pointer null (empty).
- Copy semantics are unsafe and error-prone.

****Note:**** auto_ptr was deprecated in C++11 and removed in C++17.

### 2. unique_ptr


[unique_ptr](https://www.geeksforgeeks.org/cpp/unique_ptr-in-cpp/) stores one pointer only at a time. We cannot copy unique_ptr, only transfer ownership of the object to another unique_ptr using the move() method.
![unique-pointer-in-cpp](https://media.geeksforgeeks.org/wp-content/uploads/20250402152108622799/unique-pointer-in-cpp.webp)unique_ptr
            C++

    #include &lt;iostream&gt;
#include &lt;memory&gt;
using namespace std;

class Rectangle {
    int length, breadth;

public:
    Rectangle(int l, int b) : length(l), breadth(b) {}
    int area() { return length * breadth; }
};

int main() {
    unique_ptr&lt;Rectangle&gt; P1 = make_unique&lt;Rectangle&gt;(10, 5);
    cout &lt;&lt; P1-&gt;area() &lt;&lt; endl;

    unique_ptr&lt;Rectangle&gt; P2;
    P2 = move(P1);  // ownership transfer

    cout &lt;&lt; P2-&gt;area();
    return 0;
}

**Output**50
50

Key Points

- Only one unique_ptr can own an object at a time.
- Lightweight and efficient.
- Ideal for single ownership scenarios.
- make_unique() is the recommended and safer way to create a unique_ptr.
### 3. shared_ptr


[shared_ptr ](https://www.geeksforgeeks.org/cpp/shared_ptr-in-cpp/)allows multiple pointers to share ownership of the same object. It uses reference counting to manage memory.
![shared-pointer-in-cpp](https://media.geeksforgeeks.org/wp-content/uploads/20250402152148448561/shared-pointer-in-cpp.webp)shared_ptr
            C++

    #include &lt;iostream&gt;
#include &lt;memory&gt;
using namespace std;

class Rectangle {
    int length, breadth;

public:
    Rectangle(int l, int b) : length(l), breadth(b) {}
    int area() { return length * breadth; }
};

int main() {
    shared_ptr&lt;Rectangle&gt; P1(new Rectangle(10, 5));
    shared_ptr&lt;Rectangle&gt; P2 = P1;

    cout &lt;&lt; P1-&gt;area() &lt;&lt; endl;
    cout &lt;&lt; P2-&gt;area() &lt;&lt; endl;
    cout &lt;&lt; P1.use_count();
    return 0;
}

**Output**50
50
2
### 4. weak_ptr


[weak_ptr](https://www.geeksforgeeks.org/cpp/weak_ptr-in-cpp/) is a non-owning smart pointer used with shared_ptr to prevent circular dependencies.


****Key Characteristics****

- Does not increase reference count
- Prevents circular dependency
- Must be converted using lock() before use![weak-pointer-in-cpp](https://media.geeksforgeeks.org/wp-content/uploads/20250402152221597690/weak-pointer-in-cpp.webp)weak_ptr
### Problem: Circular Dependency with shared_ptr


If two objects hold shared_ptr to each other:

- Reference count never reaches zero
- Memory leak occurs![weak_pointer](https://media.geeksforgeeks.org/wp-content/uploads/20260119112713935077/weak_pointer.webp) 

This is the reason we use ****weak pointers****(weak_ptr)  is a non-owning reference to an object managed by shared_ptr. 
![a_ptr_shared_ptr_](https://media.geeksforgeeks.org/wp-content/uploads/20260119112713984080/a_ptr_shared_ptr_.webp) 

So, in the case of shared_ptr because of cyclic dependency use_count never reaches zero which is prevented by using weak_ptr, which removes this problem by declaring A_ptr as weak_ptr, thus class A does not own it, only has access to it and we also need to check the validity of object as it may go out of scope. In general, it is a design issue.

            C++

    #include &lt;iostream&gt;
#include &lt;memory&gt;
using namespace std;

class Rectangle {
    int length, breadth;

public:
    Rectangle(int l, int b) : length(l), breadth(b) {}
    int area() { return length * breadth; }
};

int main() {
    shared_ptr&lt;Rectangle&gt; P1(new Rectangle(10, 5));
    weak_ptr&lt;Rectangle&gt; P2(P1);

    cout &lt;&lt; P1-&gt;area() &lt;&lt; endl;
    cout &lt;&lt; P2.use_count();
    return 0;
}

**Output**50
1
## Problems with Normal Pointers

- ****Memory Leaks: ****This occurs when memory is repeatedly allocated by a program but never freed. This leads to excessive memory consumption and eventually leads to a system crash.**** ****
- ****Wild Pointers: ****A pointer that is not initialized with a valid object or address is called a wild pointer.
- ****Dangling Pointers: ****Assume there is a pointer that refers to memory which was deallocated earlier in the program, that pointer is called a [****dangling pointer****](https://www.geeksforgeeks.org/cpp/dangling-pointers-in-cpp/).
